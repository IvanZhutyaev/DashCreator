# Как работает DashCreator без бэкенда

## 🎯 Механизм работы

Приложение использует **моки API** с сохранением данных в **localStorage** браузера. Это позволяет работать полностью без бэкенда.

## 📋 Архитектура

### 1. Условное переключение API

В файлах `src/lib/api/dashboards.ts` и `src/lib/api/dataSources.ts` есть логика выбора между реальным API и моками:

```typescript
const USE_MOCK = import.meta.env.VITE_USE_MOCK === 'true' || !import.meta.env.VITE_API_BASE_URL;

export const dashboardApi = USE_MOCK
  ? mockApi.dashboards  // Используем моки
  : { /* реальный API */ };
```

**Условия использования моков:**
- `VITE_USE_MOCK=true` в `.env`
- ИЛИ `VITE_API_BASE_URL` не установлен

### 2. Хранение данных в localStorage

Все данные сохраняются в браузере пользователя:

```typescript
// Ключи localStorage
'dashcreator_dashboards'     // Дашборды
'dashcreator_data_sources'   // Источники данных
```

**Преимущества:**
- ✅ Работает без бэкенда
- ✅ Данные сохраняются между сессиями
- ✅ Не нужна база данных
- ✅ Можно демонстрировать функциональность

**Ограничения:**
- ⚠️ Данные только в этом браузере
- ⚠️ Нет синхронизации между устройствами
- ⚠️ Ограничение размера (~5-10MB)

### 3. Структура моков

Моки полностью имитируют реальный API:

```typescript
mockApi.dashboards = {
  getAll()      // Получить все дашборды
  getById(id)   // Получить по ID
  create(data)  // Создать новый
  update(id, data) // Обновить
  delete(id)    // Удалить
}
```

Каждый метод:
1. Читает данные из localStorage
2. Выполняет операцию
3. Сохраняет обратно в localStorage
4. Возвращает Promise (как реальный API)

### 4. Асинхронность

Моки используют `setTimeout` для имитации задержки сети (300ms), чтобы поведение было похоже на реальный API.

## 🔄 Жизненный цикл данных

### Создание дашборда:
1. Пользователь нажимает "Сохранить"
2. Вызывается `dashboardApi.create()`
3. Данные добавляются в массив
4. Массив сохраняется в localStorage
5. UI обновляется

### Загрузка дашбордов:
1. При открытии страницы вызывается `dashboardApi.getAll()`
2. Данные читаются из localStorage
3. Отображаются в списке

### Обновление:
1. Пользователь редактирует дашборд
2. Вызывается `dashboardApi.update()`
3. Данные обновляются в массиве
4. Массив сохраняется в localStorage

## 🔌 Переход на реальный API

Чтобы подключить реальный бэкенд:

1. Создайте `.env`:
```env
VITE_API_BASE_URL=https://your-api.com/api
VITE_USE_MOCK=false
```

2. Перезапустите приложение

3. Все запросы пойдут на реальный API вместо localStorage

## 📊 Что хранится в localStorage

### Дашборды:
```json
[
  {
    "id": "123-456",
    "name": "Мой дашборд",
    "widgets": [...],
    "createdAt": "2024-01-01T00:00:00.000Z",
    "updatedAt": "2024-01-01T00:00:00.000Z"
  }
]
```

### Источники данных:
```json
[
  {
    "id": "789-012",
    "name": "REST API",
    "type": "rest_api",
    "config": {...}
  }
]
```

## 🛠️ Отладка

Чтобы посмотреть данные в localStorage:

1. Откройте DevTools (F12)
2. Вкладка "Application" → "Local Storage"
3. Найдите ключи `dashcreator_*`

Или в консоли:
```javascript
// Посмотреть все дашборды
JSON.parse(localStorage.getItem('dashcreator_dashboards'))

// Очистить данные
localStorage.removeItem('dashcreator_dashboards')
```

## ⚡ Производительность

- **Чтение**: Мгновенно (из памяти браузера)
- **Запись**: ~1-2ms (сериализация JSON)
- **Лимит**: ~5-10MB на домен

Для больших объемов данных рекомендуется использовать IndexedDB вместо localStorage.

## 🔐 Безопасность

⚠️ **Важно**: localStorage не подходит для чувствительных данных!

- Данные видны пользователю
- Можно легко изменить через DevTools
- Нет шифрования
- Используйте только для демо/прототипов

Для продакшна нужен реальный бэкенд с:
- Аутентификацией
- Шифрованием
- Валидацией данных
- Резервным копированием

---

**Итого**: Приложение работает как полноценный SPA с локальным хранилищем, что идеально для демонстрации и MVP версии! 🚀
